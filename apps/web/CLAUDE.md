# apps/web

The single deployable: one Cloudflare Worker that serves the React SPA as static assets and the Hono API under `/api`.

- `src/client/`: React app (see its CLAUDE.md)
- `src/worker/`: Hono API, queue consumer, Durable Objects, cron (see its CLAUDE.md)
- `migrations/`: D1 SQL migrations generated by drizzle-kit
- `vite.config.ts`: `react()` + `cloudflare()` from `@cloudflare/vite-plugin`, `build.sourcemap: 'hidden'`, `@sentry/vite-plugin`
- `wrangler.jsonc`: bindings and environments

## wrangler.jsonc

- `main` is `src/worker/index.ts`. Assets use `not_found_handling: "single-page-application"` and `run_worker_first: ["/api/*"]`. Keep both, or SPA routing or the API breaks.
- `compatibility_flags` must include `nodejs_compat` (Sentry needs `AsyncLocalStorage`).
- Bindings: `DB` (D1), `CACHE` (KV), `MEDIA` (R2), `EVENTS` (Queue producer on `stream-events`), `VIDEO_STATS` (Durable Object `VideoStats`), `CF_VERSION_METADATA` (version metadata), `ENVIRONMENT` var.
- Every binding must be defined for both `stage` and `production`, with separate resources per environment.
- New Durable Object classes need a new `migrations` tag (`new_sqlite_classes`). Never edit or reuse an existing tag.
- After any binding change, run `wrangler types` and commit the regenerated `Env` type.

## Secrets

Runtime secrets (`wrangler secret put`, per environment): `STREAM_ACCOUNT_ID`, `STREAM_API_TOKEN`, `STREAM_WEBHOOK_SECRET`, `TURNSTILE_SECRET`, `AUTH_SECRET`, `SENTRY_DSN`. For local dev use `.dev.vars`, which stays gitignored.

## Migrations

- Change `src/worker/db/schema.ts`, then generate with drizzle-kit. Don't hand-edit applied migrations; add a new one.
- FTS5 table and triggers (`videos_fts`) are raw SQL inside a migration, since Drizzle doesn't model them.
- Apply locally with `wrangler d1 migrations apply vidflare-db --local`. Remote apply only happens in CI.

## Local dev

`vite dev` runs the Worker in the Workers runtime with local D1/KV/R2/Queues/DO. Use `remote: true` only for Stream.
